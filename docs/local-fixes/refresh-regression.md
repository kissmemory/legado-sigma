# .7 详情与书架刷新回归修复

用户报告：书库S 3.26.1119.7 详情中的简介/收藏等书源生成信息不更新，书架批量刷新长时间等待并出现排序叠影。

## 已确认的代码路径

- 自定义版在每次晋江目录请求前额外执行详情规则；详情规则本身可包含多个请求及书源副作用。批量书架刷新因此先等待额外详情，再开始目录。
- 额外详情在Book副本执行，只复制intro与曾用名回原记录，书源写入的变量及显式更新customIntro可能丢失。
- 详情解析记录曾用名时，每本都读取bookDao.all，加载整个书架的简介和变量后再筛选。大书架批量刷新会反复分配大量无关数据。
- 手动详情刷新未明确清除搜索/发现遗留的infoHtml/tocHtml，因此可能复用旧响应。
- 通用DiffRecyclerAdapter绑定内容使用holder.layoutPosition，在重排期间可能指向旧位置；列表式书架使用默认重排动画，两类书架Diff以可变书名/作者认定行身份。

## 修复范围

- 恢复原生目录刷新路径，不为每本书额外插入详情请求；书源原有preUpdateJs/目录规则不变。详情页“刷新”强制获取新响应，在原Book上执行原书源规则，简介、收藏、标签等照书源规则更新。
- 用户手写简介仍保留，除非书源自身明确调用upCustomIntro；不把曾用名前缀存入原始简介。
- 曾用名优先按原生URL单本查询；不同URL仅扫描轻量URL键，读取同一固定ID的记录，不加载全书架完整Book。
- 用本次绑定position取书目，两个书架样式用bookUrl作行身份，列表式书架关闭重排动画以避免批量更新叠影；现有排序规则不改。
- 不修改手机数据库、配对、分组、阅读进度，不访问真实书源账号进行自动测试，不改两张电脑表。

## 验证边界

新增缓存刷新/书源变量保留/手写信息保留/轻量身份匹配回归。完整Android编译及同签名验证后另行记录产物。未运行真实手机的UI/网络验证，书源失效、原站限流或账号登录问题不在此处冒充已解决。
